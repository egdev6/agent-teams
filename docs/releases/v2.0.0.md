**Fecha de Lanzamiento:** 16 de Febrero, 2026

## 🎉 ¡Bienvenido a v2.0!

Este es un **hito importante** para Agent Teams. Hemos reimaginado completamente cómo trabajas con agentes de GitHub Copilot, pasando de la gestión individual de agentes a un poderoso **sistema de Kits & Teams** que hace que los agentes sean verdaderamente reutilizables y modulares.

---

## 🌟 Destacados

### 🎭 Equipos de Agentes Reutilizables
Crea una vez, usa en todas partes. Los agentes se adaptan a cada proyecto automáticamente.

### 📦 Sistema de Kits
Paquetes de agentes que trabajan juntos. Como paquetes npm, pero para agentes IA.

### 🔧 Composición Inteligente
Los agentes se fusionan inteligentemente con la configuración de tu proyecto. Los placeholders se resuelven automáticamente.

### 🎨 Integración con VS Code
Extensión completa con wizards interactivos. No más edición manual de YAML (a menos que lo desees).

### ⚡ Automatización CLI
Interfaz completa de línea de comandos para CI/CD y usuarios avanzados.

## 📦 Novedades en v2.0

### Características Principales

#### Arquitectura de Tres Capas

```
┌─────────────────────────────────────┐
│  SISTEMA CORE (Inmutable)          │
│  - Schemas, runtime, composer      │
└─────────────────────────────────────┘
             ↓
┌─────────────────────────────────────┐
│  KITS DE AGENTES (Reutilizables)   │
│  - Templates con placeholders      │
│  - testing-vitest, más en v2.3     │
└─────────────────────────────────────┘
             ↓
┌─────────────────────────────────────┐
│  PERFILES DE PROYECTO (Config.)    │
│  - Tus paths, comandos, tech       │
│  - Context packs, overrides        │
└─────────────────────────────────────┘
             ↓
        Agentes Finales
```

#### Perfiles de Proyecto
Configura una vez por proyecto:
- Banderas de tecnología (React, TypeScript, Vitest...)
- Mapeo de paths (`tests_root`, `src_root`...)
- Comandos (`test`, `build`, `dev`...)
- Context packs (conocimiento específico del proyecto)

#### Perfiles de Equipo
Guarda configuraciones de equipo:
- Selecciona qué kits usar
- Habilita/deshabilita agentes específicos
- Personaliza comportamiento de agentes
- Comparte entre miembros del equipo

#### Sistema de Kits
Paquetes de agentes reutilizables:
- Agentes con `{{placeholders}}`
- Requisitos tecnológicos
- Restricciones de versión
- Context packs incluidos
- Definiciones de skills

#### Agent Composer
Fusión inteligente:
- Resuelve todos los placeholders
- Fusiona context packs
- Aplica overrides
- Valida agentes finales
- Genera en `.github/agents/`

### Características Avanzadas (🧪 Experimental)

#### Context Packs Dinámicos
Motor de templates para context packs:
- Variables: `{{project:id}}`, `{{path:tests_root}}`
- Condicionales: `{{#if technology:react}}...{{/if}}`
- Loops: `{{#each technologies}}...{{/each}}`
- Includes: `{{include:kit:patterns}}`
- Filtros: `{{uppercase:text}}`

#### MergeEngine
Composición avanzada:
- 4 estrategias de merge (team, profile, kit, explicit)
- Fusión profunda anidada
- Tracking de conflictos
- Diffs visuales

#### Skills Registry
Skills centralizados:
- 30+ skills definidos
- Validación basada en roles
- Detección de conflictos
- Niveles de seguridad
- Recomendaciones inteligentes

#### Modo Dry-Run
Vista previa antes de aplicar:
- Ver qué va a cambiar
- Diffs visuales
- Sin efectos secundarios
- Experimentación segura

### VS Code Extension Commands

**New in v2.0:**
- `Agent Team: Initialize Project Profile` - Setup wizard
- `Agent Team: Create Team Profile` - Team creation
- `Agent Team: Sync Team to .github/` - One-click sync
- `Agent Team: List Teams` - Browse teams
- `Agent Team: Browse Available Kits` - Kit catalog

**Legacy (v1.0):**
- `Agent Team: Create New Agent` - Manual agent creation
- `Agent Team: Reload Agents` - Refresh agents
- `Agent Team: Select Agent` - Manual selection

### CLI Commands

**New in v2.0:**
```bash
# Profile management
agent-team profile:init

# Team management
agent-team team:create
agent-team team:sync
agent-team team:list

# Skills (experimental)
agent-team skills:list
agent-team skills:validate
agent-team skills:recommend
agent-team skills:explain
```

**Legacy (v1.0):**
```bash
# Still available
agent-team agents:init
agent-team agents:create
agent-team agents:validate
agent-team agents:sync
```

## 🎯 First Kit: testing-vitest

Included production-ready kit for Vitest testing:

**Agents:**
- `vitest-worker` - Unit and integration test creation
- `test-orchestrator` - Test strategy and coordination

**Features:**
- Technology requirements: vitest, typescript
- Placeholder paths: `tests_root`, `frontend_root`
- Placeholder commands: `test`, `test_coverage`, `test_watch`
- Context packs: testing-patterns, vitest-best-practices
- Skills: run_tests, analyze_coverage

**Usage:**
```bash
agent-team team:create --id testing --kits testing-vitest
agent-team team:sync --team testing
```

Then in Copilot Chat:
```
@vitest-worker create tests for UserService
@test-orchestrator review test coverage
```

## 🚀 Migration Guide

### From v1.0 to v2.0

**Good News:** v1.0 workflow still works! You can continue using:
- Manual agent creation (`Agent Team: Create New Agent`)
- Specs-based generation
- Old CLI commands

**But you should migrate to v2.0 for:**
- Reusable agents across projects
- Automatic configuration
- Team collaboration
- Future features

**Migration Steps:**

1. **Initialize Profile:**
   ```bash
   agent-team profile:init --id my-project
   ```

2. **Create Team from Existing Agents:**
   ```bash
   # Manually create team that mirrors your current agents
   agent-team team:create --id my-team --kits testing-vitest
   ```

3. **Configure Overrides** (if needed):
   Edit `.agent-team/teams/my-team.yml` to match your current agent settings.

4. **Test:**
   ```bash
   agent-team team:sync --team my-team --dry-run
   ```

5. **Apply:**
   ```bash
   agent-team team:sync --team my-team
   ```

6. **Cleanup:**
   Remove old spec files if desired (optional).

## 🐛 Known Issues

### v2.0.0 Release

1. **Skills validation warnings** (experimental)
   - Can be safely ignored
   - Will be stabilized in v2.1

2. **Dynamic context pack complexity** (experimental)
   - Advanced template syntax may have edge cases
   - Fallback to static packs if issues occur

3. **MergeEngine strategy selection** (experimental)
   - Default strategy works for most cases
   - Custom strategies may need tuning

4. **Extension reload required**
   - After first install, reload VS Code window
   - Some commands may not appear until reload

### Workarounds Available

All known issues have workarounds documented in:
- [QUICKSTART.md](QUICKSTART.md) - Troubleshooting section
